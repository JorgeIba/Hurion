# Stage 1: Foundation — Judge Port, Registry, and Codeforces Client

**Overview:** [00-overview.md](00-overview.md) · **Next stage:** [02-accounts-and-linking.md](02-accounts-and-linking.md)

## 0. Context for a New Contributor

Hurion is a Go Discord bot that manages competitive-programming classes. Students solve problems hosted on external sites. Each problem row (`app/data/schema.sql`, table `problems`) stores a `name` and a `url` but no judge or contest metadata. An AC (accepted solution) is a row in `solved_problems`. Today an AC is recorded in one of two ways: a mentor approves a student's proposal, or a mentor records it directly.

The feature this stage starts lets students link an online-judge account (Codeforces first), so Hurion can record ACs straight from the judge's public API. This stage builds only the foundation: the abstraction, the Codeforces parser and client, and the ADR. **Nothing is wired into the bot, the database, or Discord yet.**

Read before starting:
- `.ai/CONTEXT.md`, `.ai/TESTING.md`, `docs/ARCHITECTURE.md`
- `docs/adr/0004-problem-priority-metadata.md`: the ADR format, and the "canonical codes in `service_model`" precedent
- `app/services/service_model/model.go` and `validation.go`: where domain types and parsers live
- `app/customerr/discorderr/discord.go` and `app/customerr/dataerr/data.go`: the typed-error pattern
- `app/controllers/interactiontransport/attachment_download.go`: the existing `http.Client` injection pattern
- The Codeforces API facts in section 3 of the overview

**Prerequisites:** none. Branch `feat/judge-sync-1-foundation` from `main`.

## 1. Goal

When this stage is done:
1. ADR 0005 records the decisions in the overview.
2. A `Judge` port and a `JudgeRegistry` exist in `app/services`, together with judge-neutral domain types in `service_model`.
3. A Codeforces implementation in `app/providers/judges/codeforces` can:
   - parse problem URLs
   - look up a handle
   - fetch submissions with normalized verdicts
   - respect the rate limit
   - return typed errors
4. Everything is covered by offline unit tests. One opt-in live test proves that the real API response shapes match the decoder.

Out of scope: the database, services that use the port, Discord commands, and `main.go` wiring.

### 3.2 Domain types (`service_model/judge.go`)

```go
type JudgeCode string

const JudgeCodeforces JudgeCode = "codeforces"

// KnownJudgeCodes lists judges in the order commands offer them.
var KnownJudgeCodes = []JudgeCode{JudgeCodeforces}

// ParseJudgeCode trims and lowercases input; unknown codes return a ValidationError.
func ParseJudgeCode(raw string) (JudgeCode, error)

// ProblemRef identifies a problem on one judge. Key is judge-specific and canonical
// (Codeforces: "<contestId>/<INDEX>", e.g. "1520/B", "102222/A").
type ProblemRef struct {
    Judge JudgeCode
    Key   string
}

type Verdict string

const (
    VerdictAccepted         Verdict = "accepted"
    VerdictCompilationError Verdict = "compilation_error"
    VerdictWrongAnswer      Verdict = "wrong_answer"
    VerdictTimeLimit        Verdict = "time_limit"
    VerdictMemoryLimit      Verdict = "memory_limit"
    VerdictRuntimeError     Verdict = "runtime_error"
    VerdictPending          Verdict = "pending"   // still judging or verdict absent
    VerdictOther            Verdict = "other"
)

type Submission struct {
    ID          int64
    Problem     ProblemRef
    Verdict     Verdict
    SubmittedAt time.Time
}

// VerificationProblem is where a user submits a compilation error to prove ownership.
type VerificationProblem struct {
    Problem ProblemRef
    Name    string
    URL     string
}
```

`ProblemRef` must be comparable, so it can be used as a map key.

### 3.3 Port and registry (`services/judges.go`)

```go
//go:generate go tool mockgen -destination=mock_services/mock_judge.go -package=mock_services . Judge
type Judge interface {
    Code() service_model.JudgeCode
    DisplayName() string                                   // "Codeforces"
    ParseProblemURL(rawURL string) (service_model.ProblemRef, bool)
    VerificationProblem() service_model.VerificationProblem
    LookupHandle(ctx context.Context, handle string) (string, error) // canonical handle
    // Submissions returns newest-first submissions; limit <= 0 means the full history.
    Submissions(ctx context.Context, handle string, limit int) ([]service_model.Submission, error)
}

type JudgeRegistry struct { /* ordered judges, by code */ }

func NewJudgeRegistry(judges ...Judge) (*JudgeRegistry, error) // error on nil or duplicate code
func (r *JudgeRegistry) Get(code service_model.JudgeCode) (Judge, bool)
func (r *JudgeRegistry) Codes() []service_model.JudgeCode       // registration order
func (r *JudgeRegistry) MatchProblem(rawURL string) (service_model.ProblemRef, bool) // first judge whose parser matches
```

A nil or empty registry is valid. It matches nothing and lists no codes, so later stages can run without judges in tests.

Check how the existing `go:generate` directives in `app/services` are written and match them. If a file already declares the mock package differently, follow that.

### 3.4 Errors (`customerr/judgeerr`)

Follow the `dataerr` and `discorderr` style, with a base struct and `Unwrap`. Define:
- `InvalidHandleError`: rejected locally before any request
- `HandleNotFoundError`
- `RateLimitedError`: still limited after the retry
- `UnavailableError`: network failure, timeout, non-JSON, 5xx, or an unexpected `FAILED`

A cancelled or expired `context` is returned as an `UnavailableError` wrapping `ctx.Err()`, so `errors.Is(err, context.DeadlineExceeded)` still works.

### 3.5 Rate limiter (`providers/judges/ratelimit.go`)

```go
type Limiter struct { /* mutex, next allowed time, interval, now, sleep */ }

func NewLimiter(interval time.Duration, now func() time.Time, sleep func(context.Context, time.Duration) error) *Limiter
// Wait blocks until the caller may send one request, or returns ctx.Err().
// Calls are serialized: concurrent waiters are spaced by at least interval.
func (l *Limiter) Wait(ctx context.Context) error
```

Defaults: `time.Now` and a context-aware sleep built on `time.NewTimer` and `select`. **Do not add new module dependencies** such as `golang.org/x/time/rate`. The clock and sleep are injectable so the tests are deterministic.

### 3.6 Codeforces URL parser (`codeforces/url.go`)

Accept `http` and `https`. Accept these hosts, case-insensitively: `codeforces.com`, `www.codeforces.com`, `m1.codeforces.com`, `m2.codeforces.com`, `m3.codeforces.com`.

Accept these paths, ignoring a trailing slash, query, and fragment:

| Path | Key |
| --- | --- |
| `/contest/{c}/problem/{i}` | `{c}/{I}` |
| `/problemset/problem/{c}/{i}` | `{c}/{I}` |
| `/gym/{c}/problem/{i}` | `{c}/{I}` |
| `/problemset/gymProblem/{c}/{i}` | `{c}/{I}` |

Rules:
- `{c}` is a positive integer without leading zeros.
- `{i}` matches `^[A-Za-z][A-Za-z0-9]{0,3}$` and is uppercased (`b1` becomes `B1`).
- Everything else returns `false`, including:
  - group URLs (`/group/...`)
  - `/contest/{c}` without a problem
  - other hosts
  - `codeforces.com.evil.com`
  - `/problemset/problem/0/A`

### 3.7 Codeforces client (`codeforces/client.go`)

```go
type Options struct {
    BaseURL     string        // default "https://codeforces.com/api"
    HTTPClient  *http.Client  // default &http.Client{Timeout: 15 * time.Second}
    Limiter     *judges.Limiter // default NewLimiter(2100*time.Millisecond, time.Now, ctxSleep)
}
func New(opts Options) *Client  // implements services.Judge
```

- `Code()` returns `codeforces`. `DisplayName()` returns `Codeforces`.
- `VerificationProblem()` returns `4/A` "Watermelon" with the URL `https://codeforces.com/problemset/problem/4/A`.
- **Handle validation:** validate locally before any request. A valid handle matches `^[A-Za-z0-9_.-]{3,24}$`; anything else returns `InvalidHandleError` and sends nothing. This also blocks `;`, which would inject extra handles into `user.info`.
- **`LookupHandle`:** calls `user.info?handles=<h>` and returns `result[0].handle`. An empty result, or a `FAILED` comment containing `not found`, returns `HandleNotFoundError`.
- **`Submissions`:** calls `user.status?handle=<h>` and adds `&from=1&count=<limit>` when `limit > 0`. Decode only the fields you need. Skip submissions without `problem.contestId`. Map each submission to a `Submission`, keyed with the same canonical key format as the URL parser.
- **Verdict mapping:**

  | Codeforces verdict | Normalized verdict |
  | --- | --- |
  | `OK` | `Accepted` |
  | `COMPILATION_ERROR` | `CompilationError` |
  | `WRONG_ANSWER` | `WrongAnswer` |
  | `TIME_LIMIT_EXCEEDED`, `IDLENESS_LIMIT_EXCEEDED` | `TimeLimit` |
  | `MEMORY_LIMIT_EXCEEDED` | `MemoryLimit` |
  | `RUNTIME_ERROR` | `RuntimeError` |
  | absent, `TESTING`, `SUBMITTED` | `Pending` |
  | anything else | `Other` |

- **Each request:**
  - Call `Limiter.Wait(ctx)`, then build the URL with `url.Values` (never by string concatenation).
  - Send `User-Agent: Hurion (+https://github.com/JorgeIba/Hurion)`.
  - Read the body through `io.LimitReader` capped at 64 MiB.
  - Decode the envelope **regardless of HTTP status**: Codeforces returns `400` with a `FAILED` JSON body for bad handles. A body that isn't JSON, or a 5xx without a JSON envelope, returns `UnavailableError`.
- **Retry:** if the comment contains `Call limit exceeded`, retry **once**. The retry goes through `Limiter.Wait` again. A second limit failure returns `RateLimitedError`.
- **No credentials:** no API key and no authentication parameters.

### 4.4 Unit tests: limiter (`judges/ratelimit_test.go`)

- **Spacing:** three sequential `Wait` calls with a fake clock request sleeps that space the calls by at least the interval. Assert the recorded sleep durations. The first call doesn't sleep.
- **Gap:** after a gap longer than the interval, `Wait` doesn't sleep.
- **Cancellation:** a cancelled context returns `context.Canceled`, and the next caller's schedule isn't consumed by the cancelled call.
- **Concurrency:** N goroutines calling `Wait` together get distinct, interval-spaced slots. Run with `-race` (`make test` does).

### 4.6 Live tests (`//go:build live`)

These are excluded from `make test` and CI. Run them manually:

```
go test -tags live -run TestLive -v ./app/providers/judges/codeforces/
```

The cases, which share one client so the rate limiter applies:
1. `LookupHandle(ctx, "tourist")` returns `"tourist"` with any casing. A clearly nonexistent handle (`"hurion_no_such_user_zz"`) returns `HandleNotFoundError`.
2. `Submissions(ctx, "tourist", 5)` returns 5 or fewer submissions. Each has a non-empty key, and `SubmittedAt` is after 2010.
3. **Gym coverage**, which records a fact for the ADR:
   - Call `contest.status?contestId=100001&from=1&count=20` through a small helper (test-only).
   - Take a handle from a non-ghost party.
   - Call `Submissions` for that handle and log whether any key has a contest ID of 100000 or more.
   - The test logs this result and does not fail on it.

Paste the live test output into the PR's Verification section. If gym submissions don't appear in `user.status`, update ADR 0005 and the overview: gym problems are then unsupported in v1.
